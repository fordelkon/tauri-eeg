# 正式实验 Session 完整流程说明

适用范围：tauri-eeg **正式实验模式（发送 Trigger）**下，一名被试一次到访（session）的完整操作流程。

参数依据见[范式协议](paradigm-protocol.md)。[BioSemi 操作](biosemi-operation.md)说明设备接线、ActiView 保存与故障处理。效果评价使用[DEQ 三时点自评](momentary-assessment.md)，逐试次范式使用[SAM 自评](scale-instruments.md)。

## 0. 结论先行：session 不只有效果评价一条流程

「一个正式 session 的真正流程」要分两层看：

- **session 层（一次到访）**：五步准备 → 运行一个或多个 run → 收尾核对；研究方案另有筛查时单独安排。这套骨架对两类实验完全一致。
- **run 层（一次运行）**：run 的内容按实验目的选择，每份 BDF 对应一个 run：
  - **效果评价 run**：诱发前自评 → 视频诱发 → 诱发后自评 → 条件（自然恢复、音乐调控或视频调控）→ 条件后自评 → 结果；
  - **逐试次范式 run**：个人校准（平静 ×5 试次）或独立诱发（焦虑、抑郁、恐惧各 5 试次）。

一次到访可以只运行一种条件，也可以安排多个 run，每次运行单独保存 BDF（见 §6）。

## 1. 三个层级：session → run → 阶段

| 层级 | 含义 | 标识 | 证据位置 |
|---|---|---|---|
| session | 被试的一次到访 | BDF 文件名中的 `ses-01`（默认 01；不能仅凭文件名推断第几次到访） | 文件名 |
| run | 一次完整实验运行，前后由 run_start/run_end 包住 | run_id（界面显示前 8 位） | 实验记录页、`events.tsv`、BDF Status |
| 阶段/试次 | run 内的量表、诱发、条件窗口、逐试次序列 | 阶段事件名、试次 ID | 软件日志，有硬件触发码的事件同时核对 BDF Status 低 8 位 |

三条硬规则：

1. **一 run 一 BDF**。每次运行在 ActiView 新建文件；两个 run 不共用一份 BDF。
2. **BDF 只存脑电和触发码**（Status 低 8 位）。量表原始作答与维度得分存在应用数据库，经报告导出取用（§7）。
3. **run_start(60)/run_end(61) 由后端实验引擎统一包上**，效果评价与逐试次范式两种 run 都有（排练模式只记日志、不写硬件）。正式模式下，应用在效果评价的 run_start 写入成功后打开诱发前量表，提交后才能播放诱发视频。

## 2. 一次正式 session 的完整时间线

1. 研究方案如有入组筛查，单独安排。独立调控页的两项自评与效果评价分开记录。
2. **五步准备**（§3）：选择实验 → 连接与测试 → 准备素材 → 保存脑电 → 核对并进入。
3. **依次运行 run**（§4、§5）：每个 run 开始前重建 BDF 并重新确认保存。
4. **收尾**（§7）：ActiView Stop 封口 → 关联 BDF → 导出日志与报告 → 回读核对。

## 3. 运行前的公共准备：五步与三道门禁

| 步骤 | 关键动作 | 完成标志 |
|---|---|---|
| 1 选择实验 | 按目的选 效果评价 或 逐试次范式，再选模式（正式实验 · 发送 Trigger） | 页面显示所选流程与模式 |
| 2 连接与测试 | 刷新端口 → 选触发盒端口 → 连接；ActiView 存短测试 BDF → 发送测试码 254 → 在测试 BDF 中核对 254 | 「触发盒 已连接」+ 254 在文件中核对通过 |
| 3 准备素材 | 选择素材库根目录 → 验证并保存；音乐调控先备好曲目 | 各类视频数量齐全 |
| 4 保存脑电 | 在应用预留并复制本次正式路径 → ActiView Start 采集、Start File 粘贴该路径 → 绿色 Saving 持续增长 → 回应用核对并确认 | Saving 计数增长 + 已勾选确认 |
| 5 核对并进入 | 核对流程、模式、素材、触发盒、BDF 名 → 进入对应流程页 | 流程页顶部显示 正式实验 · run_id |

正式模式有三道门禁，缺一则正式开始被拦截（排练模式不受限）：

1. **触发盒已连接**；
2. **Trigger 测试通过**——本次连接后发送过 254 且串口写入成功（测试提示只证明写入完成，254 进入测试 BDF 才证明硬件收到）；
3. **外部保存确认**——ActiView 绿色 Saving + 应用内 BDF 记录名与实际文件一致 + 勾选确认。确认按次消耗，**每个 run 都要重新确认**。

选口陷阱：Windows 会把配对蓝牙设备（如耳机）列为 SPP 虚拟串口，向其写入恒为 0 字节并报「failed to write whole buffer」。真触发盒当前识别为 COM5（FTDI USB），以设备管理器和应用刷新端口的结果为准。

## 4. Run 类型 A：效果评价 run

### 4.1 填写与播放顺序

向导步骤固定为：**选择被试 → 诱发前量表 → 情绪诱发 → 诱发后量表 → 条件执行 → 条件后量表 → 结果评价**。

配置项：目标情绪（焦虑、悲伤或恐惧，悲伤对应抑郁类素材）、条件（基线条件 · 自然恢复｜调控条件）、手段（音乐｜视频，仅调控条件）、条件时长可选 1、3、5、10、15 或 30 分钟（自然恢复默认 1，调控默认 5）。**一个向导会话只跑一个条件**；基线条件不选手段。

### 4.2 触发码时间线

三种条件的正式序列（视频起始码按目标情绪：抑郁 1、焦虑 2、恐惧 5；视频结束统一 10）：

```text
自然恢复：60 → 2 → 10 → 70 → 71 → 51 → (静息 N 分钟) → 52 → 72 → 73 → 61
音乐调控：60 → 2 → 10 → 70 → 71 → 31 → (调控 N 分钟) → 32 → 72 → 73 → 61
视频调控：60 → 2 → 10 → 70 → 71 → 41 → (调控 N 分钟) → 42 → 72 → 73 → 61
```

T0 在诱发视频前填写，打开与提交写入软件日志。70/71 是诱发后、条件前的量表（前测）；72/73 是条件后的量表（后测）。播放异常记 90，运行中止记 91（后端）。

下列自然恢复样例来自文件 `sub-1_ses-01_task-effect.bdf`，用于核对硬件码值与先后顺序。诱发前的问卷时点需从对应 run 的软件日志核对。

| 时刻 (s) | 码 | 含义 |
|---|---|---|
| 19.714 | 60 | 运行开始 |
| 19.733 | 2 | 焦虑诱发视频开始 |
| 94.787 | 10 | 诱发视频结束 |
| 94.799 | 70 | 前测开始 |
| 153.479 | 71 | 前测提交 |
| 156.282 | 51 | 自然恢复开始 |
| 456.288 | 52 | 自然恢复结束（恰 300.00 s） |
| 458.167 | 72 | 后测开始 |
| 530.132 | 73 | 后测提交 |
| 530.145 | 61 | 运行结束 |

### 4.3 量表内容

在诱发前、诱发后、条件后用同一组 DEQ 情绪词，对焦虑、悲伤、恐惧各评 4 项，每项 1–7 分。三次均填写全部 12 项。题目依据与中文适配见[离散情绪自评](momentary-assessment.md)。

### 4.4 两段情绪变化

每种情绪分别计算诱发期间（T1 − T0）和条件期间（T2 − T1）的均分变化。正数为上升，负数为下降。

- 需要比较音乐或视频相对于自然恢复的效果时，按研究设计安排时长匹配的条件，并比较各条件的 T2 − T1。
- 若跳过剩余条件时长，报告会注明提前结束。分析时结合实际观察时长解释条件期间的分差。

## 5. Run 类型 B：逐试次范式 run

### 5.1 两种实验类型

| 类型 | 块（情绪） | 试次数 | 用途 |
|---|---|---|---|
| 个人校准 personal_calibration | 平静 calm | 5 | 采集平静基准，训练被试个性化情绪模型 |
| 独立诱发 held_out_generation | 焦虑 → 抑郁 → 恐惧 | 每类 5，共 15 | 采集各类情绪诱发反应 |

### 5.2 单试次触发码时间线

```text
93 → 20 → (试前静息 5 s) → 23 → 21 → (提示 2 s) → [1|2|3|5] → (视频 45–90 s)
   → 10 → 22 → (试后静息 5 s) → 94 → 74 → (SAM 填写) → 75
```

注意 **trial_end(94) 在 SAM 之前**：94 标记刺激阶段的结束，SAM 自评（74/75）挂在同一试次的收尾。视频起始码与情绪对应（平静 3、焦虑 2、抑郁 1、恐惧 5）。发送失败的起始标记**不会补发**；中断试次如实存为 interrupted。

质量标注（accepted｜uncertain｜rejected｜artifact_rejected）不进 BDF，随 `trials.json` 保存；SAM 质量判定不能代替离线 EEG 伪迹检查。

### 5.3 时长与注意事项

- 单试次 ≈ 12 s 固定阶段 + 视频 45–90 s + SAM 填写时间。
- 个人校准 5 试次约 8–12 分钟；独立诱发 15 试次约 25–40 分钟（粗估）。
- 范式页有**独立的模式开关**，正式运行前确认显示「正式 · 发送 Trigger」。
- 逐试次范式页默认选个人校准；做效果评价不要从范式入口进入，两者不是同一流程。

## 6. 常见 session 组合与 BDF 命名

| 研究目的 | session 内的 run 序列 | 自动预留的 task 标签 |
|---|---|---|
| 只测一个条件 | 效果评价 ×1 | 自然恢复 `effectbaseline`、音乐 `effectmusic` 或视频 `effectvideo` |
| 采集自然恢复与调控两种条件 | 自然恢复 ×1 + 调控 ×1 | 每个条件单独预留相应 task |
| 个人校准 | 范式 · 个人校准 ×1 | `calibration` |
| 独立诱发 | 范式 · 独立诱发 ×1 | `induction` |
| 全套采集 | 个人校准 → 独立诱发 → 效果 ×2 | 同次到访，四个 run 分开保存 |

应用按账号、被试、session 和 task 自动预留文件路径与 run 序号。例：`sub-001_ses-01_task-effectbaseline_run-01_eeg.bdf`。复制应用给出的完整路径到 ActiView，无需手加编号。session 默认 01，不随到访自动递增。不同到访应区分访视编号（如第二次为 `ses-02`）；当前向导没有修改该编号的入口，多次到访须另行记录并核对实际访视，不能仅凭默认文件名区分。被试 ID 建议三位零填充，应用不自动补零。正式文件与短测试文件的操作顺序见[保存脑电](biosemi-operation.md#第四步保存脑电)。

## 7. 每个 run 结束后的收尾动作

1. **先结束应用流程，再停 ActiView**：在 tauri-eeg 完成或正常中止（后端发 run_end/run_abort），然后 ActiView 点 **Stop** 封口文件头。不点 Stop 文件头记录数保持 `-1`，离线工具可能无法正常打开。
2. 实验记录 → 刷新记录 → 按 被试 ID / 开始时间 / run_id 找到本次运行，核对模式、状态与实验类型。
3. **关联 BDF 文件**；ActiView 若拆分多个文件，全部关联。
4. **导出实验日志**（`manifest.json` + `events.tsv` + `trials.json`），导出在新子目录进行，不覆盖旧导出。
5. 回读 BDF Status 低 8 位，与 `events.tsv` 中有硬件触发码的事件对照码值、顺序、数量。只核对到 254 不能证明正式事件已保存。
6. 量表与报告的导出入口：

| 导出内容 | 入口 | 格式 |
|---|---|---|
| 单次报告（三时点评分及两段变化） | 结果评价页 · 结果卡 | JSON / CSV |
| 批量汇总（每个被试、目标情绪与条件最近一次完整正式评价） | 效果评价历史记录页 | CSV |
| 实验日志 | 实验设置 · 实验记录 | manifest + TSV + JSON |

失败处理：播放或 Trigger 出错时保留失败 run 与原 BDF，重置流程重新开始一个新 run（新 BDF）；不要通过补发标记把旧记录改成正常完成。
