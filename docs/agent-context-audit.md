# 协作说明维护

换模型、换客户端或调整仓库入口时，先让一位新协作者只从 [README](../README.md) 出发，找出启动命令和受影响流程的验收证据。人、编辑器和终端代理都应能读到同一份说明。

1. **盘点并确认。** 分别统计启动时实际读入的内容、路径匹配后注入的内容、手动打开的正文。按 Unicode 字符计数，换行统一为 LF。逐段列出修、删、挪、改写、保留，写明理由、去向和行为变化，动手前确认清单。
2. **先搬后压。** 常用授权约束留根，命令和验收放普通文档。保留偏好、被否方案及原因、机器环境、静默失败、异常外观下的正常行为、半句否定约束和带日期的决定。不可逆操作的约束整段保留。删除已完工的施工稿前，核对实现、测试及可回读的 Git 版本。
3. **复核删除。** 检查旧路径引用、链接和每条路径匹配的真实文件。按旧行号对账，给独立复核者消失行与仓库，让其按含义找回约束；遗漏的原样恢复。评估某个客户端扩展是否仍被使用，看真实调用记录。
4. **验收加载。** 手动入口始终要走通。测试自动加载时，把随机暗号放在临时副本的按需正文，匹配与不匹配的文件各用一个新会话读取，检验正反结果，随后清除暗号。

项目的可选 Claude Code 钩子在匹配实验文件时提供[实验验收](verification.md)。路由测试为 `node --test .claude/hooks/context.test.mjs`；经授权使用模型额度时，`node tests/agent-context-canary.mjs` 会运行两个独立会话。

## 2026-11-15 决定

采用随仓库交付的普通文档作为协作入口。旧编排模板及其工具目录、参数和命令可用 `git show 0aea445:AGENTS.md` 回读。旧约定中的 “Use MCP tools for coordination, then keep coding” 保留其顺序：使用这类工具时，协调返回后仍需执行任务。原编排性能数字没有 EEG 产品基准证据，不作为验收指标。

本轮迁移最初用项目技能承载验证正文，独立会话曾验证路径加载，手动阅读也能找到 BDF 核验要求。为让其他协作者直接复用，正文随后移到[实验验收](verification.md)，客户端按需读取同一文件。
